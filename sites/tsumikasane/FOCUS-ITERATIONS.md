# Focus — 3周の改善と検証（2026-10-25）

## 成果物

各周のZIPは、それぞれの時点で動く端末内テスト版です。START-WINDOWS.cmd、README、Web資産、検証結果と画像、使用したソースを含みます。3周目を通常のテストに使用してください。旧版と同時には起動できません。同じブラウザ・http://127.0.0.1:4545/focus.html を使うと端末内のデータを引き継ぎます。更新前は設定からJSONを控え、開いている旧版を閉じて起動します。サイトデータは削除しないでください。

## 導線の比較

| シナリオ | 変更前 | 最終版 |
|---|---|---|
| ルーチンを切り替えて記録 | メニューを開く→項目選択→記録（3クリック） | ルーチン→記録（2クリック、1〜6個の場合） |
| 同じ下書きから記録 | 記録（1クリック） | 同じく1クリック |
| 昨日の記録 | 昨日→記録（2クリック） | 同じく2クリック、選択日は再読み込み後も復帰 |
| 計測→記録して終了 | 2クリック | 同じく2クリック、終了操作を上部へ |
| 編集中の再読み込み | 編集対象が復帰せず新規になる恐れ | 同じ記録IDへの更新として復帰 |

クリック数は内容・開始・分数が既に適切なシナリオの経路です。文字入力、ホイール調整、スクロールの手数は別です。人間の所要時間や「最適」の証明ではありません。ルーチンが7個以上のときはメニュー選択になります。

390×844の既定の集中テンプレートでは計測終了ボタン下端が約769px→約259pxへ移動。320×640でも終了操作が最初の表示範囲内にあります。テンプレート・配置・長いタイトルにより位置は変わります。

## 最終検証

- ChromiumのPC/スマホ幅で4テンプレートをそれぞれ実行（8ケース）。記録・過去日・訂正・ホイール・配置・計測復帰・タッチでの配置ドラッグ・全件書き出し・オフライン保存が合格。
- 1440×1050、390×844、375×667、320×640の追加導線検証。横はみ出しとページ例外なし。
- 設定の再起動後保持・非表示復元・段階表示を1440/390/320pxで検証。明るいテーマの濃いカレンダーセルはコントラスト比7.52。
- 1〜1440分の手入力、負数・0・小数・空欄・上限超過の拒否、予定の重複と23:59境界、実際のマウスによる時間長ホイールドラッグを検証。
- 編集中の再読み込みが新規記録を作らないこと、8031分の旧記録と開始不明の状態、予定の元の名前・メモ・追加属性を保持することを検証。
- 12種類の不正な復元ファイルで保存済み記録が変化しないことを確認。別の計測セッションは同じ開始分でも保持。タイマーが設定時間を超えて加算されないことを検証。
- 古い別タブの設定変更を競合として止めること、IndexedDBへの書き込み失敗で保存済み値と未保存の値を保持することを検証。
- アプリの通常操作は同じ端末内のGETのみ。外部リクエストなし。既存core/features/offline-cloudチェックも合格。

## 確認の限界

自動ブラウザ検証であり、人間による快適さ・作業時間の実測ではありません。Windows実機・iPhone実機・Safariでの確認は未実施。ZIPの起動はNode.js 24とEdge/Chromeを想定しています。iPhoneの初回導入にはHTTPS等の準備が別途必要です。公開や端末間同期は今回行っていません。

再現はアプリフォルダでnpm run build:focusの後、python tests/run-focus-checks.py focus-boundaries focus-browser focus-iterations:3 focus-customization:3 focus-edge-browser。Python PlaywrightとChromiumが必要です。通常使用時には不要です。結果はqa/focus-iterations/とqa/focus/に残します。
