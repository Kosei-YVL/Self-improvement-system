# ChatGPTから独立して使う

この独立版は、ChatGPTのアカウント・API・公開サーバーを使わずに動きます。Node.js 24とSQLiteで動く個人用アプリです。専用パスワードでログインし、データは自分のサーバーへ保存します。ブラウザやスマホのホーム画面から利用できます。App Store / Google Playへの登録は不要です。

現在の `chatgpt.site` で公開中の版は、引き続きChatGPTログインを使います。ホーム画面に追加するだけでは、認証やサーバーまで独立したことにはなりません。独立版の公開先は、別途用意する必要があります。

## アプリ一式を作る（ソースを持っている場合）

```bash
npm run build:standalone
```

生成された `standalone/` だけをサーバーへ移せます。実行時のnpmパッケージ追加は不要です。個人のデータ・パスワード・Sitesの設定ファイルは配布物へ入りません。

## Windowsで使い始める

Node.js 24をインストールし、独立版ZIPを解凍して `START-WINDOWS.cmd` をダブルクリックします。初回に専用パスワードを2回入力すると、設定ファイルが自動で作られます。ChatGPTへのログインはありません。次回からは同じファイルを開くだけです。

表示された `http://127.0.0.1:3000` をEdgeで開きます。データは解凍先の `data/tsumikasane.sqlite` に保存されます。起動したウィンドウを開いている間、利用できます。設定済みの `.env` は自動では上書きしません。

この方法はPC内で動かすものです。iPhoneから同じデータを利用する場合は、次の外部クラウドへの公開を使います。

## WindowsとiPhoneで、PCをつけずに共通利用する

外部サービスRender向けの公開設定を用意しています。アプリの実行、専用パスワードでのログイン、データ保存はRenderで完結します。公開後の利用にChatGPTやその契約は不要です。RenderのHTTPS URLを、Windowsではデスクトップアプリ、iPhoneではホーム画面へ追加します。独自ドメインを購入する必要はありません。

公開には自分のRenderアカウントと、コードを置いたGitリポジトリの接続が必要です。この配布物を用意しただけでは、公開・契約・課金は始まりません。

設定内容：

- Node.js 24、0.5 CPU / 512MBのWebサーバー。
- 1GBの永続ディスクへSQLiteを保存。再起動や更新でも記録を保持。
- `APP_PASSWORD_HASH` だけをRenderの秘密設定に入力。パスワードをこのチャットへ書く必要はありません。
- 公開URLはRenderから自動取得。認証前の稼働確認は `/healthz`。
- 自動公開は無効。コードを変更しただけでは稼働中のアプリを更新しません。

2026年10月18日に確認した基本料金は、サーバーUS$7/月＋ディスク1GBあたりUS$0.25/月、合計約US$7.25/月です。税・追加通信量などは別です。作成前に[Renderの最新料金](https://render.com/pricing)を確認してください。[永続ディスクは有料サーバーで利用する機能](https://render.com/docs/disks)です。この構成を無料の一時保存サーバーへ変更すると、保存データを失うため、そのまま無料プランへ変更しないでください。

このリポジトリ全体を使う場合はルートの `render.yaml` を使います。配布ZIPを別リポジトリのルートに置く場合は、ZIP内の `render.yaml` を使います。どちらも公開時に自分で作成したパスワードのハッシュを入力します。既存のデータは、下記のJSON復元で移行します。

## ターミナルから自分のPCで起動する場合

Node.js 24をインストールし、独立版のフォルダーで実行します。

```bash
npm run password:hash
```

パスワードを2回入力すると `APP_PASSWORD_HASH=...` が出ます。その1行を `.env` に保存し、次の行を追加します。パスワードそのものはファイルに保存しません。ハッシュも他人と共有しないでください。

```dotenv
APP_ORIGIN=http://127.0.0.1:3000
```

```bash
node --env-file=.env server.mjs
```

`http://127.0.0.1:3000` を開き、自分で決めたパスワードでログインします。データは `data/tsumikasane.sqlite` に保存されます。PCのローカルURLはスマホからアクセスできません。スマホ用には、以下のHTTPS公開を使います。

## スマホから使えるHTTPS公開

Dockerを使える常時稼働サーバーと、自分で管理するドメインまたはサブドメインを用意します。DNSのA/AAAAレコードをそのサーバーへ向け、80・443番ポートを開けます。サーバーとドメインには、契約先に応じた料金がかかります。

独立版フォルダーにある `.env.example` を `.env` にコピーし、以下を設定します。

- `APP_DOMAIN`：`tasks.example.com` のような実際のDNS名。
- `APP_PASSWORD_HASH`：`npm run password:hash` の結果の値。

```bash
docker compose up -d --build
```

CaddyがHTTPS証明書を取得し、`https://設定したドメイン` で開けます。アプリのデータは `app_data` ボリュームに保存され、コンテナーの更新でも残ります。アプリ内部の3000番ポートは公開しません。独立版は1人用です。複数人で別々のデータを持つ場合は、ユーザー管理を追加してください。

## 今のアプリから移行

1. 今のアプリで「自分のデータ」を開き、「履歴・データ」→「全データJSON」をダウンロードします。保存状態と、データが最新かを確認してください。
2. 独立版へログインし、「自分のデータで始める」を選びます。
3. 「データと設定」→「全データを復元する」で、そのJSONを選び、件数を確認して復元します。
4. 「クラウドに保存済み」を確認します。タスク・予定・記録・達成履歴・アーカイブ・Notion元データが引き継がれます。

URLが変わると端末の保存場所も変わるため、データは自動では移りません。移行後の確認が済むまで、元のアプリとJSONを残してください。JSON・CSV・ICSの書き出しは独立版でも使えます。

## ホーム画面へ追加

- iPhone：Safariで公開URLを開く → 共有 →「ホーム画面に追加」→「追加」。
- Android：Chromeで公開URLを開く → メニュー →「アプリをインストール」または「ホーム画面に追加」。

最初にオンラインで開き、ログインしてください。以後は通信できないときも画面と端末の控えを開けます。オフライン中の変更は、接続とログインが有効になったときにサーバーへ保存します。OSによるデータ消去に備え、JSONの控えも保管してください。

## バックアップと更新

日常の控えは画面から全データJSONを書き出します。サーバーを丸ごと移す場合は、アプリを停止してSQLiteのあるデータフォルダー／`app_data` ボリューム全体をコピーし、新しいサーバーで復元します。稼働中に `.sqlite` だけをコピーすると、WAL内の変更が抜けるため避けてください。

更新時はデータの控えを取ってからアプリを再ビルドし、`docker compose up -d --build` を実行します。`docker compose down -v` はデータを消すため使いません。画面に「新しいバージョンを開く」が表示されたら、入力を終えて選んでください。

パスワード変更は、新しいハッシュを設定してアプリを再起動します。以前のセッションは無効になります。パスワード再設定メール、複数ユーザー管理、Google Calendarの自動同期は、この版には含まれません。Google連携は独立版のドメインに対するOAuth設定を別途行えます。
