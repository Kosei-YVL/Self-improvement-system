# Focus — 同期・移行・開発分離版

## 今回の範囲

PC・スマホで同じルーチン、タスク、予定、記録、履歴、元データを共有する仕組みです。通常の画面はFocusのまま、同期・移行は設定にまとめています。配置・テーマは端末ごとです。進行中の計測も端末間で共有します。現行の3画面の操作はFOCUS-THREE-SCREEN.mdを参照してください。

外出先を含む実際の端末間利用には、両端末から開ける同じHTTPSのURLが必要です。今回はクラウド公開を行っていません。localhostのZIPをPCで起動しただけではiPhoneから接続できません。

## Windowsでのローカルテスト

Node.js 24以上でINSTALL-FOCUS.vbsを開くと、デスクトップとスタートメニューにFocusを追加します。以後はアイコンから非表示でサーバーを起動し、画面を開けます。詳細はFOCUS-WINDOWS.md。手動起動用のSTART-WINDOWS.cmdも残しています。URLはhttp://127.0.0.1:4545/focus.html のままです。同じブラウザとプロファイルを使えば既存のIndexedDBを引き継ぎます。最初の起動でアプリフォルダの隣のfocus-data/personal/にサーバーDBとsync-key.txtを作成します。同期キーを設定→端末間同期に貼り付けます。

ブラウザの別プロファイルでも同じURLと同期キーを使うと、端末ごとの保存領域を分けた同期テストができます。URLが変わるクラウドへの移行時は、旧版からJSONを書き出して、新しいURLで復元してから同期します。別URLの保存領域は自動で読み取れません。

## 共有と保護

- IndexedDBに先に保存し、その後に同期します。通信断でも記録を継続し、復帰後・画面に戻った時・操作後・画面を開いている間の約15秒ごとに同期します。OSがアプリを停止している間は実行しません。
- 同期キーは32バイトのランダム値。端末でAES-256-GCMにより暗号化し、認証用の別の派生値だけをAPIへ送ります。サーバーへ復号キーは送りません。HTTPSも必須です。キーは紛失しないよう保持してください。手元のJSONからは復元できますが、サーバーだけでは復号できません。
- 独立した追加・編集はIDを保って統合。同じ項目への異なる変更は確認待ち。解決前に両方を書き出し、同期前の復元ポイントも端末に最大5件保持します。削除と編集で整合性が取れない場合は自動反映を止めます。
- サーバーは暗号化した最新3世代を保持。サーバーの保存履歴が端末より古い場合は自動上書きを止めます。1同期要求の上限は16MiB。超えても端末内データは保持し、ZIPを書き出せます。
- キーはブラウザ内に保存するため、端末のロックが前提です。端末内データや書き出しファイルそのものを自動暗号化する機能ではありません。

## 別アプリへの移行

設定→移行用ZIP。focus.jsonが全データを保持する基準ファイルです。追加属性・アーカイブ・履歴・Notion由来の元データも残します。routines.csv / tasks.csv / records.csv / schedule.csv / history.csv とschedule.ics、archive.json、source-tables.jsonも含めます。

日時はAsia/Tokyo、時間長は分、実測は秒、IDは安定したIDです。開始不明は空欄。CSVはUTF-8 BOMと引用符を使い、表計算の数式として解釈される先頭文字にはアポストロフィを付けます。元の値はfocus.jsonにあります。移行先の仕様に合わせた列の対応付けは必要で、全アプリがそのまま読めることは保証できません。同期キー・認証情報は書き出しません。

Focusバックアップv1、旧データv1/v2を読み込みます。未知の新バージョンは変更前に拒否します。復元前の全体控えをダウンロードし、端末内にも最大5件保存します。設定→復元ポイントを書き出すと、各控えを復元可能なJSONにしたZIPが得られます。新しい未対応形式で開けない場合も「元データを書き出す」から未変換の控えを残せます。データ移行で元データを破棄しません。

## 既存データを使い続けながら開発する

ソースのnpm run build:focus:syncが普段使い用、npm run build:focus:devが開発用です。

| 項目 | 普段使い | 開発 |
|---|---|---|
| URL | 127.0.0.1:4545 | 127.0.0.1:4546 |
| IndexedDB | tsumikasane-device-v1 | focus-development-v1 |
| サーバーDB | focus-data/personal/focus.sqlite | focus-data/development/focus.sqlite |
| 同期先の環境 | personal | development |

開発版には「開発」と表示します。環境が一致しないAPI要求はサーバーが拒否します。ビルド出力だけを再作成し、focus-data/を削除しません。DB・キーはGitや配布ZIPに含めません。テストは一時ディレクトリと架空データのみで実行します。

日常データを開発に入れる場合も、JSONのコピーを開発版で読み込みます。普段使いのDBへの直接接続はしません。更新前にJSONを控え、開発版で旧形式の復元・CRUD・同期・書き出しを確認してから普段使い版のコードだけを更新します。データ形式はバージョンを上げて読み込み変換を追加し、元のバックアップを残します。

## 無料枠のクラウドへ接続するための用意

Cloudflare Workers + D1用のworker、schema.sql、wrangler.jsoncを同梱しています。アカウント作成・接続・公開は未実施です。無料枠には容量・処理回数などの上限があり、常に無料とは断言しません。有料契約は今回行いません。

自分のCloudflareアカウントでD1を作り、wrangler.jsoncのdatabase_idを設定、focus-server/schema.sqlを適用します。SYNC_AUTH_HASHには次の専用生成ツールが出力する認証用ハッシュをsecretとして登録し、同期キーは端末だけに入力します。wrangler secret put SYNC_AUTH_HASH、wrangler d1 execute focus-personal --remote --file=focus-server/schema.sql、wrangler deployが設定手順です。キーをコードやGitへ書かないでください。開発用は別Worker・別D1・別キーにします。

公開後はPC・iPhoneともそのHTTPS URLを開き、同じ同期キーを設定します。iPhoneはSafariの共有→ホーム画面に追加。ChatGPTのログインは使いません。

## 自動配置とローカルAI

同期の土台と、自動配置・AIは別モジュールにできます。時間帯・所要時間・期限・優先度・固定予定を入力として、制約計算で配置案を更新する方式ならAI利用料なしで動作します。Googleカレンダーの自動読み取りには別途OAuth接続が必要です。ローカルAIモデルやGoogle連携は今回の成果物には未搭載です。Webアプリを閉じたiPhoneで常時実行することはできません。
